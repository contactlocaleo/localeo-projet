# Périmètre de preuve

- La session Chrome prouve la lecture du carnet rempli, la reprise sur le même appareil, les consignes du lot libre et le retour. Les transitions de remise, d’expiration et d’annulation n’ont pas été provoquées. Aucun bon à code d’un autre type n’a été présenté.
- Les inscriptions existaient déjà. Le QR valide, le code du jour, la soumission, la réception d’un nouveau lien et la reprise sur un autre appareil restent à tester avec des accès ou données dédiés.
- Le programme futur est vide dans l’aperçu Bouliac. Le 404 et la 429 historiques ne sont pas reproduits dans la passe publique actuelle. Leur fréquence et leurs causes restent à qualifier. [Réponses publiques de cette exécution](trace-public.json) · [Réponses historiques](../../2026-11-23/observations/preuve-contrepoints.json)
- L’émulation Chrome couvre trois largeurs pour le carnet. Les détails ont été examinés à 390 px. L’usage avec lecteur d’écran et clavier virtuel sur appareil et les tests habitants restent ouverts. L’identification entre le commit local et la version déployée n’a pas été prouvée.
- Le nom du responsable du lot est groupé avec la preuve métier sur deux écrans. Il est masqué sur les deux preuves archivées. Les captures de la session ne contiennent ni code de bon, ni accès personnel transmissible.
