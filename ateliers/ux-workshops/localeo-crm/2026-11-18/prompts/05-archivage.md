# ÉTAPE 5 — ARCHIVAGE ET REJOUABILITÉ WORKSHOP LOCALEO CRM

Tu es chargé de finaliser l'archivage du workshop UX Localeo CRM.

## 1. Répertoire

Identifie l'exécution en cours dans :

`docs/ux-workshops/localeo-crm/YYYY-MM-DD/`

Ne modifie pas les exécutions précédentes.

## 2. Vérification des prompts

Contrôle :

- `prompts/00-protocole-global.md`
- `prompts/01-exploration.md`
- `prompts/02-workshop.md`
- `prompts/03-maquettes.md`
- `prompts/04-validation.md`
- `prompts/05-archivage.md`

Chaque fichier doit contenir le prompt complet réellement utilisé.

Enregistre cette instruction dans `prompts/05-archivage.md`.

Si une instruction a évolué, documente la modification.

Ne fabrique pas de version historique.

## 3. Vérification des livrables

Contrôle :

- Observations.
- Cartographies.
- Captures.
- Rapport exécutif.
- Votes nominatifs.
- Backlog.
- Orientations rejetées.
- Quick wins.
- Maquettes.
- Galerie comparative.
- Décisions.
- Roadmap.
- Plan de tests.

Signale les éléments manquants.

## 4. Synthèse

Crée dans `synthese/` :

- `roadmap-ux.md`
- `plan-tests-utilisateurs.md`

La roadmap distingue :

- Avant lancement : P0/P1 validées.
- Après premiers retours : P2.
- Évolutions futures : P3.

Le plan de tests doit prévoir au moins six scénarios réels :

1. Première connexion.
2. Consultation du tableau de bord.
3. Qualification d'un prospect.
4. Planification d'un rendez-vous.
5. Gestion des relances.
6. Pilotage collectif.

Pour chaque scénario, définis les consignes neutres, les observations et les critères de réussite.

## 5. Finaliser le README

Indique :

- Date et heure.
- URL analysée.
- Branche et commit Git.
- Modèles et niveaux de raisonnement connus.
- Version du protocole.
- Parcours vérifiés.
- Limitations.
- Nombre d'orientations proposées.
- Nombre d'orientations adoptées.
- Nombre de P0/P1.
- Statut des validations.
- Liens vers les livrables.
- Statut final.

## 6. Comparaison historique

Si un workshop CRM précédent existe, crée :

`synthese/comparaison-precedent.md`

Compare :

- Les problèmes corrigés.
- Les problèmes persistants.
- Les nouveaux problèmes.
- Les changements de priorité.
- Les évolutions des notes heuristiques.
- Les orientations validées et reportées.

Ne présente comme corrigé qu'un problème dont la résolution a été vérifiée.

## 7. Préparer la relance

Crée :

`prompts/RELANCER-WORKSHOP.md`

Le prompt doit permettre de :

1. Identifier le dernier protocole.
2. Créer un nouveau répertoire daté.
3. Réexplorer le CRM réel.
4. Rejouer le workshop.
5. Organiser les votes à la majorité.
6. Prioriser P0 à P3.
7. Produire les maquettes.
8. Comparer les résultats.
9. Préserver l'historique.
10. Attendre ma validation.

Il doit être autonome.

## 8. Vérification finale

Vérifie :

- L'intégrité des fichiers.
- Les chemins.
- Les captures.
- Les maquettes.
- Les prompts.
- La préservation des anciens workshops.
- L'absence de modification applicative.
- L'absence de données sensibles dans les livrables.

Si le workshop est incomplet, indique-le.

## 9. Restitution

Présente :

- Le répertoire archivé.
- Le statut.
- Les livrables.
- Les anomalies éventuelles.
- Le chemin du prompt de relance.

Ne réalise aucune modification applicative.
