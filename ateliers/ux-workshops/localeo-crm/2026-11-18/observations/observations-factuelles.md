- Routes UI et API : `localeo-backend/app/api/crm_ui.py:13`, `app/api/prospection_api.py:177-264`, `app/api/prospection_rendez_vous_api.py:167-215`, `app/api/prospection_rappels_api.py:79-184`.
- Shell et composants : `app/infrastructure/pwa/crm/crm.js:132` (navigation), `:462-475` (création et rapprochement), `:479-532` (Aujourd'hui et indicateurs), `:547-629` (filtres Prospects/Suivi) ; `crm-agenda.js:95-123` (agenda), `:164-282` (disponibilités/réservation), `:305-370` (détail, modification, report, réalisation, annulation).
- Règles et persistance : `app/domaine/prospection/`, `app/application/prospection/`, `app/infrastructure/persistence/prospection_core.py` et `prospection_rendez_vous.py` ; schéma SQL `sql/v290_crm_prospection.sql`, `v294_crm_responsable_prospect.sql`, `v311_crm_rendez_vous.sql`, `v312_crm_rendez_vous_notifications.sql`.
- Statuts et invariants : `app/domaine/prospection/regles.py` définit les étapes du dossier `A_CONTACTER`, `DISCUSSION`, `PROPOSITION`, `GAGNEE`, `PERDUE`, `PAUSE`, ainsi que le contrôle des ressemblances ; `app/domaine/prospection/tache.py:19-35` porte les transitions de tâche ; `app/domaine/prospection/rendez_vous.py:147-210` porte les statuts `PLANIFIE`, `VALIDE`, `REALISE`, `ANNULE`, le contrôle du responsable et les conflits de disponibilité. La couche applicative orchestre ces règles dans `app/application/prospection/service.py` et `rendez_vous.py`.
- Notifications : API `prospection_rappels_api.py:79-184`, interface `crm-agenda.js:376`, worker PWA `app/infrastructure/pwa/crm/push-worker.js` et adaptateur `app/infrastructure/communication/rappels_crm.py`.

Ces repères démontrent une implémentation locale lisible. Ils ne valident ni son déploiement exact, ni l'efficacité du parcours pour un utilisateur.
